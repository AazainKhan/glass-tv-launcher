# Device-agnostic audit (P155)

Rule (CLAUDE.md cf77259): every feature works per install mode (APK / Glass Pro / Glass OS) and on any Android TV or Google TV device, not just the Fire TV Stick 4K 2nd gen (AFTKRT "karat", Fire OS 8). This table lists every Fire- or karat-specific value in `app/` and the Magisk modules, what happens on a non-Fire box today, and the fix. "Detect" means a runtime check, never a build flag.

Detection used: `HomeSetup.isFireTv` (manufacturer Amazon or model AFT*), a package-installed check, or a path/prop existence check, whichever names the real dependency. The generic default is always the stock Android behaviour or nothing.

| # | Item | Where | On a non-Fire box today | Fix |
|---|---|---|---|---|
| 1 | Stock launcher packages (`com.amazon.tv.launcher`, `com.amazon.firehomestarter`) and its HOME activity | `RootFeatures.kt` STOCK_HOME, `setHomeTakeover`, `keepHome` | Takeover "on" disables nothing; "off" runs `set-home-activity com.amazon.tv.launcher/...` which fails | Stock launchers are found at runtime: every HOME-resolving package that is not Glass; restore uses the activity the system resolves for it. Control hidden when there is none. |
| 2 | GPU / CPU min-freq sysfs (`/sys/class/devfreq/13000000.gpu`, `policy0`) | `RootFeatures.kt` GPU, CPU, `profileScript` | Already guarded by `[ -w path ]`; window-animation scale part is generic | Keep; the Performance control shows only when one of the paths is writable. |
| 3 | lmkd props (`ro.lmk.*`), `max_cached_processes=12`, 1.2 GB zram fstab overlay | `RootFeatures.setMemoryTuning`, `tools/magisk/glass-tuning`, `scripts/tuning` | Tuned from measurements on a 2 GB karat; wrong on 4 GB+ boxes (a 1.2 GB zram overlay creates a stray `/vendor/etc/fstab.enableswap`) | Memory tuning offered and its service.sh run only on Fire with ≤ 2.5 GB RAM; the module's service.sh exits otherwise; the install script refuses without `/vendor/etc/fstab.enableswap`. |
| 4 | `persist.perfanimation.enabled` (Fire OS Home-key flash) | `RootFeatures.reapplyAtStart` | Creates an unused prop | Only when the prop already exists (`getprop` non-empty). |
| 5 | Fire's AutoPairService, `persist.sys.auto_pair_sys_service`, own remote pairing | `RootFeatures.setOwnRemotePairing`, `RemotePairer`, `tools/magisk/glass-remote-keepalive`, `scripts/remote-keepalive` | Prop is set for nothing; the keepalive service follows a log tag that never appears, forever | Own-pairing control only on Fire; keepalive service.sh exits unless `ro.product.manufacturer` is Amazon. |
| 6 | `glass-remote-keys`: key layout `Vendor_0171_Product_0427.kl`, `glass-keymap remap "Fire TV Remote" 249 185`, BUTTON_9..13 codes | `scripts/remote-keys`, `tools/magisk/glass-remote-keys/service.sh` | Install aborts with "unexpected key layout" (safe); on a box that happens to have gamepad BUTTON_9..13, `RemoteKeysService` would launch apps from a gamepad | service.sh exits off Fire; install says why; `RemoteButtons.actionFor` treats `KEYCODE_BUTTON_9..13` as remote buttons only from an Amazon remote's input device, the standard APP_1..4/RECENTS/APP_SWITCH names stay generic. |
| 7 | Default remote button apps (`com.amazon.firebat`, `com.amazon.bueller.music`) and the `amzn://apps/android` fallback | `RemoteButtons.all`, `RemoteKeysService.kt:197` | Prime/Music not installed: opens an `amzn://` link nothing handles | Defaults to a not-installed app are skipped; the store fallback is `market://details` on non-Fire. |
| 8 | Appstore (`com.amazon.venezia`), `navigate_node`, enabling Amazon's launcher as root | `AmazonStore.kt`, `MainActivity.kt` store request, `GlassApp.kt` close | Never triggered without the Appstore; `close` is a cheap no-op unless a visit is pending | Store request path ignored unless venezia is installed (already the case by referrer); documented. |
| 9 | Fire Settings sections and actions (`com.amazon.tv.settings.v2`, `com.amazon.device.settings.action.*`) | `SystemControls.kt` | Every one has a standard `Settings.ACTION_*` fallback | Keep; fallbacks verified on the AVD. |
| 10 | Alexa page and tiles (`com.amazon.vizzini`, smart-home map, mic key 217, Alexa settings via root) | `CcLayout.default` "alexa" page, `SystemControls.openSmartHome/askAlexa/openAlexaSettings`, `AlexaIcon` | A dead Alexa page in Control Center | The default layout adds the Alexa page only when the Alexa app is installed; saved layouts keep it hidden while it is not. |
| 11 | Amazon debloat list (OTA, metrics, Appstore, Prime Video...) | `RootFeatures.FREEZABLE`, `scripts/debloat` | Rows for packages that are not there | List shows only installed packages. |
| 12 | Hidden-package lists (`HomeModel` hides `com.amazon.*` system apps) | `HomeModel.kt` | Harmless: the packages are absent | Keep. |
| 13 | `queries` for `com.amazon.vizzini`, the `amzn` scheme filter | `AndroidManifest.xml` | Harmless | Keep. |
| 14 | Fire-only Settings pages (Fire screensaver note, Home takeover) | `SettingsPanel.kt` via `HomeSetup.isFireTv` | Already gated | Keep. |
| 15 | Remote watch / pairing by name (`RemotePairPolicy.isAmazonRemoteName`) | `RemoteWatch.kt`, `RemotePairer.kt` | Acts only on Amazon-named remotes | Keep. |
| 16 | `Build.MODEL.startsWith("AFT")` | `HomeGuard.kt` `isFireTv` | This is the detection | Keep. |

Out of scope here: the privileged-app allowlist `scripts/privapp-check` and the `glass-system` module are about the privileged install mode, which is per-device on purpose.

## Status (what this change did)

Done in code: 1 (stock Home found at run time; Takeover row hidden with none), 3 (`DeviceProfile.memoryTuningApplies`: Fire and at most 2.5 GB; module and install script refuse elsewhere), 4, 5 (Own Remote Pairing row only on Fire; keepalive module and install refuse off Fire), 6 (remote-keys module exits off Fire; `RemoteButtons.actionFor` takes the input device's name and ignores BUTTON_9..13 from a non-remote), 7 (Play store link off Fire), 10 (Alexa page and its Settings switch only with the Alexa app), 11 (App Freezer lists installed packages only). Items 2, 8, 9, 12 to 16 needed no change (already guarded, harmless or already generic). `glass-tuning`'s zram overlay file is applied by Magisk before any script runs, so the install script refuses unless the device has `/vendor/etc/fstab.enableswap`.
